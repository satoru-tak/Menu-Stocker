# ビジョン文書

> このプロジェクトが「誰の・どんな困りごとを・どう解決するか」を1ページで言い切る文書。
> 新しい機能を足したくなったとき、「それはこのビジョンに合っているか？」と立ち返る基準になる。

---

## 1. 一言で言うと

**「おうちを、自分だけのお店に。」**

動画やWebで見つけたレシピを**かんたんに自分のレシピとして保存**し、アレンジ・評価・振り返りを書きためて**自分だけのレシピ帳**に育て、それを**お店のようなメニュー表**にして、**お店の気分**を味わえるアプリ。料理を**自分の趣味・自分の世界**として楽しむためのものであり、その世界を家族や友人に見せて一緒に楽しむこともできる。

## 2. 解決したい困りごと

- 一度作った料理を見返すたびに、**レシピ動画を最初から見直すのが大変**
- 元のレシピに加えた**自分なりのアレンジを残す場所がない**
- 人数に合わせて**分量を毎回計算し直すのが面倒**
- 作るほど「**どれが美味しかったっけ？**」「**前に作ったの何だっけ？**」が分からなくなる
- 1週間分などの献立を決めても、**必要な材料をまとめて出すのが大変**
- 毎日の料理が「作業」になり、**趣味としてのワクワクがない**

## 3. 誰のためのものか

- 中心は、料理を**自分の趣味として楽しみたい人**。レシピを集めて育て、自分のお店を開くように楽しむ。まずは **自分** のためのアプリ（第1段階）
- 家族や友人は「主役」ではなく、**自分の世界を見せて一緒に楽しめる相手**。見せる・共有するのは楽しみ方の1つ
- ゆくゆくは、**すべての人が楽しく料理と向き合える**アプリへ（将来段階）

## 4. 何を実現するか（このアプリの約束）

1. **かんたん保存** — 入力が大変でないこと。画像も貼れて、自分だけのレシピ表になる
2. **自分のレシピ化** — 元のレシピを残したまま**アレンジ**を重ねられる。人数に合わせて**分量を自動換算**できる
3. **評価と振り返り** — 点数・レビュー・「次はこうしたい」を書きため、レシピを**自分の好みに合わせて育てられる**。「作った」記録で、いつ何を作ったかが分かる
4. **整理** — ジャンル（和風・洋風・おつまみ・デザート・一品料理など）を自由に作って分類できる
5. **メニュー表** — 献立（例：1週間分）を、テーマを選んで**お店のメニュー表**のように表示できる
6. **材料の逆算** — 献立から必要な材料を買い物リストにできる

### 差別化（競合にないもの）

競合調査（2026年11月時点）で、次の3つは主要なレシピアプリに見当たらなかった。ここを磨くことを最優先にする。

- **テーマ付きのメニュー表**（家庭の献立を「お店の体験」に変える）
- **アレンジの系譜**（オリジナル → アレンジ1 → アレンジ2 をアレンジ履歴に残して比べられる）
- **レシピを育てる**（アレンジ履歴と作った記録で、何をどう変えてきたかを残す）

一方、AIでの取り込み・分量調整・買い物リスト・ハンズフリー操作は**競合ではすでに当たり前の機能**であり、差別化ではなく「いずれ必要な前提」として扱う。

## 5. 使う場面

- **キッチン（スマホ）** — 作りながら確認する。手が汚れていても「見る・確認する・操作する」がかんたんにできること。登録は主にここではない
- **PC・スマホでじっくり** — レシピを登録・アレンジ・振り返りを書く
- **自分のお店を開く** — メニュー表を眺めて楽しむ。家族や友人に見せたり、画像・PDFに書き出してLINE・X・Instagramで共有したりする

## 6. やらないこと（スコープ外・第1段階）

ビジョンをぶらさないため、当面やらないことも明記しておく。

- ログイン・公開・ほかの人とのレシピ共有（第1段階は自分専用、ローカル完結）
- AIによるレシピの自動取り込み（第2段階以降で追加。まずは入力しやすい手入力フォーム）
- ブログ・日記の公開、収入化
- 栄養・カロリー計算
- 注文・決済（LINEからの注文、モバイルオーダーなど）

## 7. 将来の展望（メモ）

### 段階

- **第1段階：自分用**（ローカル完結）— 差別化の3つを形にする。社内の事業提案のデモにもなる
- **第2段階：検証** — 少人数に使ってもらい、有料で使ってもらえるか・メニュー表が使われるかを確かめる。AI取り込みもこのあたりで検討
- **第3段階：公開版** — ログイン、ユーザー間の共有、SNS共有のリンク化
- **第4段階：収益化** — レシピの公開・ブログ、料理家の収益化

### 事業化の方針

- このプロダクトは個人ではなく**自社（新規事業）として育てる**前提
- 収益はサブスクだけでは薄い（試算では有料会員約2,000人で損益分岐）。大手と同様に**企業向け（食品メーカーとのタイアップ等）**を収益の柱として検討する
- SES会社としての価値：AIを使った開発（ハーネス・ループ）の実績、エンジニア育成、自社プロダクトによる採用・営業面のアピール

### 企業モード（構想メモ）

- 飲食店などが**営利目的でメニュー表を作るモード**。ロゴ・価格を入れ、PDFで店に並べ、スマホ（QR）でも見られる
- 強みは**レシピ（材料・分量）とメニューがつながっている**こと。原価率・値付けまで出せる点はデザインツールにも外注にもない
- 個人向けより高めのサブスク。同じアプリにするか別ブランド（例：Menu Stocker for Business）にするかは第3段階ごろに判断する。メニュー表を作る仕組みは共通にする
- 注文・決済は対象外
- データ設計の方針（組織・店舗）は `03_data_model.md` の「将来の拡張」に記載する

### そのほか

- 公開・事業化の段階では、レシピや画像の権利（取り込んだ元レシピ・動画の扱い）、レビューの著作権の検討が必要になる

## 8. デザイン・体験についてのメモ

- **配色は未確定**。方向性は「食欲が湧く・清潔感・温かみ」。候補は**B'（テラコッタ＋生成り＋からし色／焦げ茶）**：オレンジ系で料理アプリらしさを保ちつつ、くすんだ温かい色調（手帳・素焼き・木の器）でクラシルなどのオレンジ＋グリーンと差をつける
  - 背景は青み・灰色を避け、温かい中間色にする（料理写真が冷たく見えないように）
  - 強い色で目立たせるボタンは1画面に1つ
- **アプリ本体とメニュー表は別の世界観**。アプリ本体はレシピと写真が主役なので控えめに。メニュー表はテーマ（レストラン・和食屋・料亭・居酒屋・ファミレス風など）ごとにまったく別のデザインにする。実在の店のロゴや見た目はまねない
- **キッチンでの操作性**：大きめの文字とボタン、高いコントラスト、少ない操作で「見る・確認する」ができること
- 単なる管理の効率だけでなく、レシピを**育てる楽しさ**、**お店の気分を味わえるワクワク感**、それを人に見せたくなる仕上がりがあるかを必ず検討すること
