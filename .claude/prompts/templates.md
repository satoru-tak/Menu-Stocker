# Claude Code 開発プロンプトテンプレート

## 基本プロンプト

以下のテンプレートを使用して、Claude Code に指示を出すことで、一貫性のある高品質なコードを生成できます。

---

## 1. 機能実装プロンプト

```
【機能名】: [機能の名前]

【目的】: [この機能が解決する課題や提供する価値]

【要件】:
- [要件1]
- [要件2]
- [要件3]

【技術仕様】:
- Backend: [使用する技術やライブラリ]
- Frontend: [使用する技術やライブラリ]
- データベース: [必要なテーブルやカラム]

【実装手順】:
1. [手順1]
2. [手順2]
3. [手順3]

【テスト項目】:
- [テスト1]
- [テスト2]

【参考】:
- 関連ファイル: [ファイルパス]
- 参考ドキュメント: [ドキュメントパス]

【その他】:
- 日本語でコメントを記述
- 規約に従ったコーディング
- テストコードも同時に作成
```

**使用例:**
```
【機能名】: レシピ作成機能

【目的】: ユーザーが新しいレシピを登録できるようにする

【要件】:
- レシピ名、説明、調理時間、難易度を入力できる
- 材料を複数追加できる
- 調理手順を順番に追加できる
- 画像を1枚アップロードできる

【技術仕様】:
- Backend: Rails API, Active Storage
- Frontend: Next.js, React Hook Form, TailwindCSS
- データベース: recipes, ingredients, steps テーブル

【実装手順】:
1. Backend: Recipe モデルとコントローラーの作成
2. Backend: API エンドポイントの実装
3. Frontend: レシピフォームコンポーネントの作成
4. Frontend: API 連携の実装
5. テストの作成

【テスト項目】:
- レシピが正常に作成できる
- バリデーションエラーが適切に表示される
- 画像アップロードが動作する

【その他】:
- docs/api/README.md に API 仕様を追記
- 日本語コメントで実装
```

```
【セキュリティ対策の種類】:
[認証/認可/データ保護/入力検証など]

【対策内容】:
[具体的にどのような対策を実装するか]

【対象範囲】:
- [対象の機能やエンドポイント]

【参考資料】:
- [セキュリティのベストプラクティス]
- [OWASP Top 10 など]

【テスト方法】:
[セキュリティ対策が正しく動作するかのテスト]
```

---

## 使用時の注意点

1. **具体的に指示する**: 曖昧な表現を避け、具体的な要件を記載
2. **段階的に進める**: 大きな機能は小さく分割して実装
3. **テストを忘れない**: 実装と同時にテストコードも作成
4. **ドキュメントを更新**: コード変更時は関連ドキュメントも更新
5. **レビューを依頼**: 生成されたコードは必ずレビューする

## よく使うフレーズ

### コード生成
- "〇〇機能を実装してください"
- "〇〇のバグを修正してください"
- "〇〇をリファクタリングしてください"

### ドキュメント
- "〇〇のAPI仕様書を作成してください"
- "〇〇のER図を作成してください"
- "〇〇の設計書を更新してください"

### レビュー
- "このコードをレビューしてください"
- "このコードの問題点を指摘してください"
- "より良い実装方法を提案してください"

### 説明
- "〇〇について説明してください"
- "〇〇の仕組みを教えてください"
- "〇〇のベストプラクティスを教えてください"
